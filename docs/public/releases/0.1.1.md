# Transist 0.1.1

This public beta patch corrects bounded-loop successor routing and updates
workspace dependencies. The runtime remains pre-1.0; existing support and
stability limits are unchanged.

## Bounded Loop Routing

- Newly compiled recipes explicitly select loop-routing version 1. Reaching an
  activation's `max_iters` cap takes the loop's normal successor rather than
  silently skipping it.
- Approval guards still execute and must succeed before parent publication.
  Exhausting the iteration budget never implies approval.
- Marked loop guards see null for a declared body's initial, reset, or suspended
  business output. Unknown references and malformed predicates remain fail-closed.
- Prospective validation, explanations, and inspection include cap-inclusive exits
  and validate downstream authority, schemas, and prerequisites before run birth.

## Adoption and Recovery

Prepared recipes without routing metadata retain legacy routing, including on
resume and replay. To adopt the fix, compile new recipes and start new runs with
this runtime; replaying an old recipe does not opt it into the new semantics.

Preserve each runtime home with its matching runtime and reviewed bundle for
recovery. Never strip routing metadata or downgrade a marked home. Use a fresh
home for a newly reviewed bundle when changed same-version package bytes conflict
with an installed identity. Rollback means returning to the preserved matching
runtime/home pair; it does not undo external effects.

Runtime, admin, and server versions are `0.1.1`. Bundled workflows, modules,
plugins, and exact catalog pins remain `0.1.0`. Schema and protocol identifiers
remain `v1`; the routing marker does not rename a schema or grant authority.
