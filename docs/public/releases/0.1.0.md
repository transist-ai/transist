# Transist 0.1.0

Transist's initial public beta is a governed local execution runtime for explicit
AI and automation workflows. It coordinates tools, services, models, and human
actions through authored workflows while keeping local state authoritative.

## Capabilities

- Declarative `transist.flow.v1` workflows and `transist.module.v1` modules with
  typed dataflow, bounded control flow, manual gates, and named outputs.
- Managed documents with immutable revisions and exact-revision human review.
- Frozen run recipes, pinned assets, durable execution history, and explicit
  retry, resume, replay, cancellation, and matching terminal cleanup.
- Versioned plugin packages with process, HTTP, and MCP adapters.
- Standalone evaluation and governed execution with signature verification,
  explicit capability grants, secret-delivery policy, and local-only enforcement.
- Deterministic workflow explanation, probe-free validation, and separate live
  readiness checks before execution.
- CLI/TUI inspection, a read-only companion API, and Prometheus metrics.

Trust creation belongs to `transist-admin`; the runtime verifies and enforces
trust. Explanation, validation, and human review do not themselves execute work.

## Install and Evaluate

Use the signed archives from
[GitHub Releases](https://github.com/transist-ai/transist/releases/tag/v0.1.0).
The six target triples are:

- `x86_64-unknown-linux-gnu`
- `x86_64-unknown-linux-musl`
- `aarch64-unknown-linux-gnu`
- `aarch64-unknown-linux-musl`
- `aarch64-apple-darwin`
- `x86_64-apple-darwin`

Each archive includes `transist`, `transist-server`, `transist-admin`, the shell
plugin, offline quickstart, demo workflows, and authoring skills. Linux archives
also include the sandbox launcher. Follow
[artifact verification](../reference/release-artifact-verification.md) before
the [quickstart](../guides/getting-started/quickstart.md). Python 3 is required
for the bundled shell plugin; Linux requires bubblewrap and usable user namespaces.

## Compatibility and Limits

Runtime and bundled package versions are `0.1.0`; runtime-owned contracts use
`v1`. This is pre-1.0 software, not a stability or production-readiness promise.
There is no Windows distribution, distributed scheduler, mandatory hosted
service, or supported public Rust library distribution.

Start in a fresh runtime home. Installed package identities are content-immutable;
changed same-version bytes require a newly reviewed bundle and a fresh home when
an installed identity conflicts. Preserve homes and their matching runtime and
reviewed bundles together. Replay and rollback do not undo external effects.

See [Compatibility and Stability](../reference/compatibility-and-stability.md),
[Known Limitations](../reference/known-limitations.md), and
[Supported Platforms](../reference/supported-platforms.md).
